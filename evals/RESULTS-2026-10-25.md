# Scenario results, 2026-10-25

First run of the six behavior scenarios in `evals/`. Scores are reported as the tool produced them. Graders were not changed after seeing the results; known grader problems are listed separately, with what the transcripts actually show.

## Setup

- Command: `claude plugin eval . --runs 2 --scaffold --allow-tools Write Edit Bash --no-publish --keep-temp`, Claude Code 2.1.278, Fedora Linux, OS sandbox (bubblewrap).
- Agent model: `claude-sonnet-5` (Claude Code default). Judge model for `llm` graders: `haiku` (default), 3 votes each.
- Two arms per case: **with** the plugin and **without** it (baseline), 2 runs each: 24 runs in total.
- S1, S3, S4, S5 and S6 ran with Python packages `sqlglot` and `duckdb` on `PATH`. S2 ran with the system Python, which has no `sqlglot`: that is the condition it tests.
- Each run is isolated: no user settings, memory, `CLAUDE.md` or other plugins. Prompts do not name the skill, so whether it triggers on its own is part of the test. It triggered in all 12 runs with the plugin.
- Estimated cost: $7.27 for the suite, plus $0.57 for one earlier smoke run of S5.

## Per scenario: what the transcripts show

**S1, ambiguous rule.** With the plugin, both runs listed the two definitions with their counts on the sample data (4 customers vs 5, only 2 in common), asked which applies, and left the SQL unimplemented. The run scored 0.75 is a grader false negative: the agent added a comment `BLOCKED: ... status='A' flag vs. order in last 90 days ...` to the SQL file, and the regex matched the comment. A real slip in that run: it edited the existing SQL file (to add that comment) without a backup, which principle 5 asks for. Without the plugin, both runs noticed the ambiguity but one implemented the 90-day definition anyway ("I implemented the metrics.md definition... tell me if you meant status='A'").

**S2, missing tool.** With the plugin, both runs stated that `sqlglot` was missing, declared a reduced mode and labelled the translation as hand-written and not verified, with what to check before go-live. One run opens with "is ready" and puts the caveat in the next paragraph; the caveat should come first. Without the plugin, both runs delivered a hand translation with no mention of a missing tool or of verification.

**S3, code only. This is a real failure.** With the plugin, both runs declared `code-only`, listed the concrete differences (inner join and `is_active`, NULL types dropped by `<>`, per-row rounding), labelled everything as not verified and wrote diagnostic queries. But run 1 called the join "the candidate of largest magnitude" and rounding "unlikely to be the main cause" before any test: that is ranking causes by likelihood, which principle 10 forbids. Run 2 put the diagnostic queries only in `findings.md`, not in the reply, so the user in the chat does not see them. One "replies in Spanish" FAIL looks like a judge error: that reply is in Spanish. Without the plugin, both runs gave good hypotheses and queries but also ranked a likely cause; they scored higher because their answers were short and self-contained in the chat.

**S4, change applied.** With the plugin, both runs backed up `models/b.sql`, applied the approved change, measured −655.46 against the expected −555.46, ran `waterfall.py compare`, reported the mismatch (a third repeated line, D010) and left the case open. Without the plugin, both runs also noticed the mismatch and did not close, but neither made a backup.

**S5, overwrite.** With the plugin, both runs copied the file before editing and stated the backup path. Without the plugin, neither made a copy.

**S6, full reconcile.** With the plugin, both runs found the missing credit notes (+47.75) and the repeated lines (+555.46), produced the waterfall with the bundled script, reported the 0.0103 residual within the 0.1428 tolerance from the Spec, and left "do credit notes count?" and "are the repeated lines real duplicates?" to an approver. Without the plugin, both runs found the same two causes but described the residual loosely ("a few cents") and declared both causes engine bugs needing no sign-off ("likely a join fan-out bug"): an untested cause and a business decision taken by the agent.

## Known grader problems (not fixed in this run)

- S1 `03-sql-not-implemented` matches comments, not only SQL logic.
- S3 `04-replies-in-spanish` failed once on a reply that is in Spanish.
- The `llm` graders with `focus: trace` only see the first and last 12 messages; S5 was switched to regex graders for that reason before this run.

## What to change next

- Skill, `code-only` mode: order hypotheses by test cost and power, never by likelihood, and put the diagnostic queries in the reply as well as in `findings.md`.
- Skill, S2: put the "not verified" caveat before the deliverable.
- Skill, S1: a comment added to an existing file is still an overwrite; back it up.
- Graders: strip comments before the S1 regex; rerun S3 with more runs to separate judge noise from behavior.
- Coverage: run the same suite on a smaller model and on other agents.
